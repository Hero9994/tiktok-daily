# ناشر صور TikTok اليومية

مشروع Python وGitHub Actions لترشيح **فيلم أو مسلسل مختلف يوميًا**، ببطاقة عمودية تحمل اسمه ونبذة عربية دون حرق الأحداث، مع **وصف ثابت و5 هاشتاغات ثابتة**، ثم نشرها عبر **Buffer GraphQL API الحالي**. يحفظ السجل والصور في فرع `bot-state`، ويؤكد الإرسال من حالة Buffer `sent`. يمكن العودة إلى نمط الصور الفنية العامة باختيار `content_mode: art`.

## كيف نكمل دون رفع الملفات يدويًا؟

1. مستودع `tiktok-daily` العام موجود الآن؛ يتولى الوكيل رفع الملفات وتشغيل اختبار Actions. لا حاجة لرفع الملفات يدويًا.
2. افتح [Buffer](https://buffer.com/signup)، ثم [Channels](https://account.buffer.com/channels) واختر TikTok وسجّل الدخول إلى الحساب المطلوب واقبل صلاحية النشر. هذا هو ربط TikTok؛ لا ترسل كلمة المرور أو رمز الدخول إلى الوكيل.
3. ضع مفتاح Buffer ومفتاح OpenAI في GitHub Actions Secrets حسب الخطوات أدناه. يعرف المشروع حساب TikTok من قناة Buffer، ولا يحتاج مفتاح TikTok منفصلًا. الوكيل يستخرج معرّفي القناة والمؤسسة عبر `discover` ثم يضبط الربط.
4. حدّد نص وصفك الثابت، والوقت والمنطقة الزمنية. يتولى الوكيل اختبار منشور واحد والتأكد من `sent` قبل تشغيل الجدولة. إنشاء مستودع وحده لا يربط TikTok ولا يمنح مفاتيح OpenAI/Buffer.

النمط الجديد يقرأ نبذة موثقة من Wikipedia دون مفتاح إضافي، ثم يصوغ منها نبذة عربية موجزة. الصورة رسم أصلي مستوحى من أجواء العمل، لا بوستر رسمي أو صورة ممثل. يكتب اسم العمل والنبذة محليًا بخط Noto Sans Arabic المرخص OFL، لضمان اتصال الحروف العربية. تبقى بيانات المصدر في سجل المنشور للمراجعة. إن لم يتوفر مصدر مناسب يتوقف بدل اختلاق معلومات.

**الحالة:** المشروع مبني ومختبر محليًا؛ مستودع [Hero9994/tiktok-daily](https://github.com/Hero9994/tiktok-daily) متاح الآن وقد خصصه المستخدم للمشروع. ربط OpenAI وBuffer والنشر الحقيقي لم يتمّا بعد. التشغيل والإنفاق معطّلان في الإعدادات الافتراضية. [تقرير الاختبار](docs/TEST_REPORT.md) و[التوثيق الرسمي والتكلفة](docs/VERIFICATION.md).

## الربط لأول مرة

1. استخدم حساب GitHub الموجود، وأنشئ مستودعًا **عامًا** من [New repository](https://github.com/new)، أو خصّص مستودعًا عامًا موجودًا للمشروع. ارفع محتويات هذا المجلد إلى فرعه الافتراضي `main`. احتفظ بمجلد `.github` أيضًا. الصور والسجل سيكونان عامّين؛ المفاتيح تحفظ في Secrets فقط. هذه الطريقة لا تحتاج حساب استضافة صور. الاتصال الحالي يستطيع العمل على المستودعات الموجودة، لكن GitHub رفض إنشاء مستودع جديد بصلاحياته الحالية.
2. أنشئ حساب [Buffer Free](https://buffer.com/signup)، واربط حساب TikTok من [Channels](https://account.buffer.com/channels) بقبول الصلاحيات. تأكد من تشغيل **Automatic publishing** وأن القناة غير موقوفة، ولا تتطلب الموافقة على كل منشور. أنشئ المفتاح من [Settings → API](https://publish.buffer.com/settings/api). لا تشترك في خطة مدفوعة.
3. أنشئ حساب [OpenAI API](https://platform.openai.com/)، وأضف رصيدًا حسب الحد الأدنى الذي يعرضه حسابك، ثم أنشئ مفتاح مشروع مخصص. اشتراك ChatGPT لا يغطي تكلفة API. قد يُطلب توثيق المؤسسة لاستخدام الصور. راجع التكلفة أدناه قبل إضافة الرصيد.
4. في GitHub: **Settings → Secrets and variables → Actions → New repository secret**، أضف `OPENAI_API_KEY` و`BUFFER_API_KEY`. لا تضع المفاتيح في الكود أو المحادثة أو `.env` المرفوع.
5. يتولى الوكيل تشغيل **Actions → Daily TikTok → discover**، ثم يضبط `buffer_organization_id` و`buffer_channel_id` في `config.json` من نتيجة الربط. المعرّفات إعدادات غير سرية وليست مفاتيح API؛ لا تحتاج إضافتها يدويًا إلى Secrets. إذا ظهرت عدة قنوات اختر حسابك المطلوب. يمكن أيضًا حفظ المعرّفات في Secrets بالأسماء `BUFFER_ORGANIZATION_ID` و`BUFFER_CHANNEL_ID` إن رغبت.
6. تأكد من تفعيل Issues. في **Settings → Actions → General → Workflow permissions** اسمح للـworkflow بالكتابة، وأزل أي حماية تمنع حساب Actions من كتابة فرع `bot-state` فقط. فعّل إشعارات فشل Actions في حساب GitHub، واشترك بإشعارات المستودع/قضية الفشل لتصل إلى بريدك.
7. حدّد الوصف الثابت والوقت والمنطقة الزمنية؛ يتولى الوكيل ضبط `config.json`. شغّل `doctor` أولًا؛ يجب أن يتوفر مفتاحا OpenAI وBuffer، وأن تصبح `channel_configured` و`fixed_caption_ready` قيمتين صحيحتين. بعد مراجعة التكلفة غيّر `enabled` و`allow_paid_openai` إلى `true` واحفظ التعديل على `main`.
8. للاختبار الحقيقي الأول اختر `publish-test`؛ **يولّد صورة مدفوعة وينشرها على TikTok فورًا**، ويحتسب منشور اليوم. ثم اختر `verify` بعد دقائق وافتح رابط المنشور الموجود في `bot-state/state.json` عندما تصبح الحالة `sent`. إذا بقيت `accepted` فالمنشور لم يُؤكَّد بعد. بعد نجاح الاختبار شغّل `prepare` لتجهيز الموعد التالي؛ تستمر الجدولة اليومية تلقائيًا.

ربط TikTok وفوترة OpenAI يحتاجان تسجيل دخولك وقبول الصلاحيات. إذا سمحت برفع المشروع إلى مستودع GitHub موجود، يمكن للوكيل تنفيذ الرفع باستخدام الاتصال الحالي؛ لا حاجة لإعادة كتابة المشروع أو رفع ملفاته يدويًا.

## التعديل اليومي

| الإعداد | الاستخدام |
|---|---|
| `theme` | تفضيلات ترشيح الأفلام والمسلسلات، أو موضوع الصور في نمط art |
| `content_mode` | `cinema` للأفلام والمسلسلات أو `art` للصور الفنية |
| `fixed_caption` | نص الوصف الثابت دون هاشتاغات؛ يلزم تحديده قبل تفعيل نمط cinema |
| `style` | `paper_cut`، `watercolor`، `pixel_art`، `flat_vector`، `oil_painting` |
| `publish_time` | الوقت المحلي بصيغة `HH:MM` |
| `timezone` | مثل `Asia/Riyadh` أو `Asia/Beirut`؛ يراعي التوقيت الصيفي |
| `hashtag_pool` | مجموعة يختار منها النموذج ما يلائم الصورة؛ 5 فريدة على الأقل |
| `fixed_hashtags` | هاشتاغات ثابتة من 0 إلى 5؛ لا يزيد المجموع عن 5 |
| `image_quality` | `low` اقتصادي، أو `medium` أعلى تكلفة |
| `max_image_requests_per_month` | سقف طلبات الصور، الافتراضي 31، والمحاولات الفاشلة تدخل في العدد |
| `enabled` | إيقاف العمليات الجديدة والفحص الدوري؛ المنشورات المقبولة سابقًا تبقى في Buffer |

التحضير يعمل يوميًا **03:17 UTC**، ويجهز أقرب موعد محلي يبعد ساعة على الأقل. Buffer يتولى النشر عند `publish_time`. يعمل فحص التسليم كل ساعة عند الدقيقة 43. يمكنك تغيير الموعد المحلي من JSON دون تعديل cron. إذا غيّرت توقيت التحضير نفسه في workflow فعدّل كذلك مطابقته في خطوة `Run publisher`. لا تغيّر النموذج إلى خيار أغلى دون مراجعة الأسعار وتعديل التحقق في الكود.

## التكلفة والقيود

- **Buffer:** الخطة المجانية تشمل API: مفتاح واحد، 100 طلب/15 دقيقة، 250/24 ساعة، 3,000/30 يومًا. صف الانتظار المجاني يستوعب 10 منشورات للقناة. الاستخدام العادي للمشروع أقل بكثير؛ لا تستخدم المفتاح ذاته لأتمتة كثيفة أخرى.
- **GitHub Actions:** مجاني على المستودعات العامة عند استخدام المشغّلات القياسية كما هنا. لا يرفع المشروع Actions artifacts ولا يستخدم مشغّلات أكبر مدفوعة. المستودع الخاص يحتاج استضافة صور أخرى ومراجعة حصته وتكلفته.
- **OpenAI:** مدفوع. جدول الصور الرسمي يذكر **$0.005** لمخرجات صورة `gpt-image-2` بدقة `1024×1536` وجودة `low`، أي **$0.15 لمخرجات 30 صورة**، إضافةً إلى مدخلات الصورة والنص وتوليد الفكرة. `medium`: **$0.041 للصورة، أو $1.23 لمخرجات 30 صورة**. الإعادات قد تزيد التكلفة. النموذج النصي الاقتصادي الموثّق `gpt-6-luna`: $0.10/مليون رمز إدخال و$0.50/مليون إخراج في Standard للسياق القصير. الأسعار قابلة للتغيير، والضرائب والحد الأدنى للشحن يختلفان؛ لا يوجد وعد بتكلفة فاتورة ثابتة.
- الصورة تُولّد اقتصاديًا بدقة `1024×1536` ثم تُقصّ إلى نسبة 9:16 وتُحجّم بجودة Lanczos إلى **1080×1920 JPEG**. هذه أبعاد ملف النشر النهائي؛ ليست دقة التوليد الأصلية. يبقى الموضوع في وسط الصورة لتقليل أثر القص.
- يدعم Buffer صور TikTok، لكنه **يرفض `isAiGenerated` على الصور**. يبدأ كل وصف بإفصاح عربي صريح عن التوليد بالذكاء الاصطناعي. إرشادات TikTok تسمح بإفصاح واضح في الوصف أو الملصق أو العلامة المائية. المسار الافتراضي محافظ: فن خيالي دون أشخاص أو أحداث حقيقية أو إعلانات؛ لا يوهم بأن صورة خيالية حقيقية. فحص OpenAI Moderation إضافي، ولا يضمن وحده الالتزام بكل سياسات TikTok.
- الجدولة المجانية أفضل جهد: GitHub قد يؤخر أو يسقط بعض التشغيلات، وقد يعطّل الجدولة بالمستودعات العامة بعد 60 يومًا دون نشاط. سجلات التشغيل والبيانات محفوظة؛ راقب تعطيل workflow أو انتهاء تفويض TikTok. لا يمكن ضمان تشغيل دائم بلا أي صيانة حسابات.

## منع التكرار والفشل

يحجز المشروع تاريخ النشر مع قناة TikTok ويحفظه في Git **قبل** طلب Buffer. يحفظ معرّف المنشور وموعده وفكرته وبصمتي الصورة. في نمط cinema يمنع إعادة العمل نفسه اعتمادًا على معرّف صفحة Wikipedia، حتى لو غيّر النموذج صيغة الاسم. يسمح بتكرار الوصف الثابت ويستخدم عنوان العمل مع الوصف لمطابقة المنشور عند استعادة نتيجة إرسال غامضة. في نمط art يفحص الوصف المكرر أيضًا. يعطي النموذج آخر 365 عملًا في نمط cinema أو آخر 60 فكرة في art؛ السجل الكامل يبقى متاحًا لفحص التكرار. فحوص التشابه البصري واللغوي تقريبية.

يعيد محاولات القراءات مع تأخير تصاعدي. لتوليد الفكرة حد 3 طلبات لليوم، وللصورة 3 محاولات للمنشور مع سقف شهري يحجز قبل الطلب. عند نتيجة إرسال غير مؤكدة يقرأ منشورات Buffer عبر كل الصفحات لاستعادة المعرف؛ **لا يعيد طلب النشر تلقائيًا** لأن Buffer لا يوفر مفتاح idempotency على `createPost`. إذا لم يحسم النتيجة يتوقف ويرسل تنبيهًا عبر فشل Actions وقضية GitHub واحدة تُحدَّث برابط التشغيل، دون أسرار أو نص ردود API.

`accepted` يعني أن Buffer قبل المنشور. `sent` وحدها تؤكد نجاح التسليم بحسب Buffer. يرسل تنبيهًا إذا بقي غير مرسل بعد 90 دقيقة من موعده أو صار `error`/`draft`/`needs_approval`/نشرًا بالإشعار. لا يعدّل أو يحذف منشورًا فعليًا تلقائيًا. للتوقف عن نشر صور تمت جدولتها مسبقًا، أوقف القناة أو احذف المنشورات من Buffer أيضًا.

**التعافي:** افتح قضية الفشل وسجل التشغيل وBuffer. صحّح ربط القناة أو الصلاحيات، ثم شغّل `verify`. إذا كانت الحالة `uncertain` ولم يُعثر على المنشور، لا تمسح السجل ولا ترسل مرة ثانية قبل فحص Scheduled/Sent/Drafts والتأكد من عدم وجوده. الحالات المرفوضة لتاريخ معيّن لا تُرسل مجددًا تلقائيًا؛ تشغيل اليوم التالي لا يعيد المنشور المرفوض. لا تحذف فرع البيانات، ولا تكتب فيه بالتوازي مع workflow، فقد تفقد دليل منع التكرار.

## تجربة محلية مجانية

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m tiktok_daily doctor
python -m tiktok_daily preview
```

`preview` يرسم عينة محلية في `output/sample.jpg` مع وصف في `sample.json`، دون اتصال أو إنفاق أو نشر. الصورة التجريبية ليست مولّدة من OpenAI. اختبارات النشر تستخدم استجابات محاكاة؛ اختبار Git ينفذ فرعًا ورفعًا واستعادة حقيقيين إلى مستودع محلي مؤقت.
